# AsyncPulse

Локальный портфолио-проект на FastAPI: конкурентный агрегатор десяти воспроизводимых HTTP API с адаптивным планировщиком. Python 3.11+.

## Быстрый запуск

```bash
uv sync --extra dev
uv run uvicorn asyncpulse.mock:app --port 8001
```

Во втором терминале из этой же директории:

```bash
uv run uvicorn asyncpulse.main:app --port 8000
```

Swagger: http://127.0.0.1:8000/docs. Локальный режим использует ограниченный TTL-кеш в памяти; PostgreSQL не требуется.

Полный стек с Redis и PostgreSQL:

```bash
docker compose up --build
```

```bash
curl -X POST http://127.0.0.1:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"iphone","use_cache":false}'
```

Ответ содержит статус поиска, данные и ошибки каждого источника, длительность и признак попадания в кеш. Сбой одного внешнего API не прерывает остальные. `completed` означает, что все источники обработаны; результаты отдельных источников могут содержать ошибки.

## API и отмена

| Маршрут | Назначение |
| --- | --- |
| `POST /search` | Дождаться агрегированного результата; разрыв соединения отменяет поиск |
| `POST /search/jobs` | Поставить поиск в очередь, ответ 202 с UUID |
| `GET /search/{id}` | Получить состояние и результаты |
| `DELETE /search/{id}` | Идемпотентно отменить поиск |
| `WS /search/{id}/ws` | Получать снимки прогресса; сообщение `cancel` отменяет поиск |
| `GET /sources` | Список разрешённых источников |
| `GET /metrics` | Метрики Prometheus |
| `GET /health` | Состояние процесса и размер очереди |

Тело запроса: `query`, необязательные `sources` (например, `["shop-0","shop-1"]`), `mode` (`concurrent` или `sequential`), `use_cache`. URL источников задаются на сервере, клиент выбирает только их имена.

```javascript
const response = await fetch('http://127.0.0.1:8000/search/jobs', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({query: 'iphone'})
});
const job = await response.json();
const ws = new WebSocket(`ws://127.0.0.1:8000/search/${job.id}/ws`);
ws.onmessage = event => console.log(JSON.parse(event.data));
```

Закрытие WebSocket отменяет ещё активный поиск. При нескольких наблюдателях это общая отмена задания. Для фонового поиска без этого поведения используйте polling через GET. WebSocket передаёт актуальные снимки, промежуточные состояния могут объединяться для медленного клиента.

## Как работает конкурентность

`asyncio.Queue` ограничена 64 заданиями; восемь workers исполняют поиски. При заполнении очереди API отвечает 503 с `Retry-After`. Хранилище содержит не более 1000 заданий: завершённые удаляются первыми, их UUID после удаления возвращают 404.

Один `httpx.AsyncClient` переиспользует соединения. `Semaphore` допускает не более 32 HTTP запросов одновременно. `TaskGroup` управляет жизненным циклом запросов одного поиска. `asyncio.timeout` ограничивает отдельный HTTP запрос двумя секундами и весь поиск 15 секундами, включая ожидание слотов и retry после начала работы worker.

Для каждого источника адаптивный gate стартует с двух слотов. После серии быстрых успешных ответов лимит растёт до восьми; при 429, 5xx, таймауте или медленном ответе уменьшается вдвое, минимум до одного. Уменьшение не обрывает уже активные запросы. Rate limiter разносит старты запросов с частотой до 20 в секунду на источник. До двух повторов выполняются с exponential backoff и jitter; числовой `Retry-After` учитывается с верхней границей пять секунд. Необратимые 4xx и неверный JSON не повторяются.

Одинаковые запросы к одному источнику объединяются через общий task и `Lock`. `asyncio.shield` защищает задачу от отмены одного ожидающего. Последний ушедший ожидающий отменяет HTTP запрос, ожидает завершения и освобождения слотов. Запросы с разными `use_cache` не объединяются. `asyncio.gather` используется для ожидания и очистки отменённых задач и workers.

Redis хранит общий между процессами кеш ответов с TTL 60 секунд. PostgreSQL сохраняет JSON завершённых поисков, включая частичные результаты и отмены. Схема создаётся на старте для демонстрации; в production потребуются миграции. `processing.py` содержит отдельные примеры: экспорт через `asyncio.to_thread` для блокирующего файлового I/O и хеширование через `ProcessPoolExecutor` для CPU-bound работы. Они не добавляют искусственную CPU нагрузку в поиск. Отмена ожидания CPU операции не останавливает уже работающий процесс; завершение пула ожидается в потоке.

## Воспроизводимые эксперименты

Mock API по умолчанию отвечает через 500 мс. Запросы `rate-limit`, `failure`, `slow` воспроизводят 429, 503 и таймаут. `MOCK_DELAY` задаёт задержку mock, `MOCK_URL` — его базовый URL для агрегатора. `REDIS_URL` и `DATABASE_URL` включают внешние хранилища. Остальные параметры находятся в `asyncpulse/config.py`.

```bash
uv run pytest
uv run ruff check .
uv run python scripts/benchmark.py
```

Бенчмарк делает по пять последовательных и конкурентных поисков без кеша, проверяет отсутствие ошибок и сохраняет сырые измерения и медиану в `artifacts/benchmark.json`. Теоретическое время десяти источников по 500 мс: около пяти секунд последовательно и 500 мс конкурентно. Реальные измерения конкретного локального запуска приводятся в `BENCHMARK.md`.

```bash
mkdir -p artifacts
uv run locust -f load/locustfile.py --host http://127.0.0.1:8000 \
  --headless -u 20 -r 5 -t 60s --csv artifacts/load --csv-full-history
uv run python scripts/plot_load.py artifacts/load_stats_history.csv
uv run python scripts/memory.py <PID_ПРОЦЕССА_UVICORN>
uv run python scripts/plot_memory.py
```

Сценарий Locust использует уникальные запросы без кеша и считает частичные/неуспешные поиски ошибками. График `artifacts/load.png` показывает p50, p95, throughput и ошибки в секунду. RSS пишется отдельно в `artifacts/memory.csv`; запускайте сбор памяти одновременно с нагрузкой. Метрики Prometheus дают число попыток по исходам, гистограмму времени внешних запросов и текущие адаптивные лимиты. Метрики внешних запросов не эквивалентны end-to-end latency поиска.

Для автоматического запуска всего эксперимента с временными серверами и их остановкой:

```bash
uv run python scripts/run_experiment.py
```

Порты 8000 и 8001 должны быть свободны. Этот сценарий использует кеш в памяти и отключает внешние хранилища для измерений.

## Границы проекта

Это локальная демонстрация без авторизации. UUID задания даёт доступ к его данным и отмене. Запускайте один Uvicorn worker: задания, coalescing, очередь и rate limiter живут в одном процессе, Redis разделяет только кеш. Несколько реплик потребуют распределённой очереди, владельцев заданий и общего лимитера. Подключение к PostgreSQL и Redis должно работать при включённых URL; ошибки инфраструктуры отражаются в состоянии поиска. `/health` проверяет процесс, а не готовность внешних хранилищ.

1000 одновременных клиентов не создадут 1000 активных поисков: восемь выполняются, 64 ждут в очереди, остальные получают backpressure. Кеш памяти ограничен 10000 ключами. Нет неограниченной очереди фоновых tasks. История PostgreSQL требует собственной политики хранения; demo не удаляет старые записи.
